# Endpoint Coverage

Every call and callback in the reference client's surface, and what this client
does with each. The table below is generated by `scripts/gen_api_docs.py` from
the source: CI regenerates it on every push and fails if what is committed has
drifted from the code.

Three things to read it with:

* **The status is per call, not per feature.** `Y` means the call is served on
  that surface. `STUB` means it exists with the expected signature and does not
  reach the venue. What each stub is and why is on [Limits](./limits.md).
* **The evidence column is derived.** A call is credited to the live session
  only when a suite that opens a session names it, and to the offline suites
  only when a test names it. Nothing in that column is hand-maintained, so
  nothing in it can go quietly out of date — and nothing in it is a promise
  that the call was exercised in the way you intend to use it.
* **Coverage is not correctness.** A call that reaches the venue can still be
  the wrong call for what you are doing. The behaviour notes are in
  [capabilities.md](https://github.com/userFRM/ibx/blob/main/docs/capabilities.md).

For which messages this client speaks, rather than which method names it
carries, see [Wire Coverage](./wire-coverage.md) — taken from the dispatch
tables and the message builders themselves.
